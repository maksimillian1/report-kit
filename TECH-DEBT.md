# Kit tech debt

| # | Task | Why | Evidence |
|:--| :--- | :--- | :--- |
| 1 | Placeholder authoring mode: a report writes `{{FD07}}` and the build renders the value, instead of writing the number and marking it with a ref | marking verifies an existing corpus; placeholders make drift impossible by construction, and remove the one blind spot marking keeps — two figures with the same value can be mis-anchored and the check still passes. Worth it for a report authored from scratch, which is the kit's case | `examples/simple-api`: `share_r04`, `share_r12` and `share_r24` all print `100`, and the three `unserved_r*` all print `0.0`; `examples/async-jobs`: `tier_ms` and `retry_units` both print `60`. A mark anchored to the wrong one of a group still passes `check` |
| 2 | Decide whether the metric register itself should be YAML | a ref is currently defined in three places — the register table, `series.txt` and `guards.txt` — and only the last two are machine-read. One source would generate the table and both pipe files | `refs.py` parses the pipe files; the register table is hand-kept beside them |
| 3 | Make `renumber` refuse, or warn loudly, when a delete would shift refs that documents already cite — and offer to rewrite the marks | refs are tool-assigned so reclassifying is cheap, but deleting a figure silently invalidates every mark above it in every document. The tool renumbers the registry and cannot rewrite prose, so the damage is only visible if someone re-runs the check and reads the count | `examples/simple-api`: deleting `served_r04` shifts 17 `FM` refs, all 17 already cited in `report.md` and `execution.md`. `renumber` prints the new per-kind counts and nothing else; where two figures print the same value (row 1) even a re-run of `check` stays quiet |
| 4 | Take the `orphans` token shape from the registry — a `meta.orphans` pattern with one group around the digits — instead of the hardcoded `MONEY` | a command that answers "none" for every report it cannot read is worse than no command: it reads as a clean bill of health. Today `orphans` is meaningful only for a report priced in dollars, and says nothing about one measured in anything else | `tools/figures.py:60` — `MONEY` requires a `$`. Both worked examples print `none` for `report.md`, not because they are clean but because they are measured in ms, req/s and %. A dollar-denominated registry over a comparable report finds 13 tokens, so the command does work — for one kind of report |
| 5 | Drop the `unit == "hours"` branch from `display()`; let `display:` be the only thing that sets precision | the tool guesses on the author's behalf, and the guess is a coin flip: one report's hours are whole, the next one's are 4.5 — and that one gets silently written as `4`. A unit is what a number measures, not how it prints | `tools/figures.py:54` (`HOURS_DECIMALS = 0`) and `:356` (the branch). Used by two figures in one consuming report and by zero figures in either example. The replacement already exists and is already tested: `tests/test_figures.py` has `hours_forced`, which proves an explicit `display=1` overrides the branch |
| 6 | Replace the figure names and numbers of one consuming report in the docstrings with neutral placeholders | the kit is a general-purpose library, and names belonging to somebody else's report mislead the next reader. Lowest priority of the three: nothing behaves differently, it only reads wrong | `tools/figures.py:5,6,7,11` (`block_b_total`, `FD26`, `--group totals`, `d23_n25`), `:487-488` (`$554`, `553.83`, `0.0952`), `:369` ("a floor, a sweep, a campaign"), `:74` ("a price quoted") |
| 7 | Make the plotted series an obstacle for label placement, so a label cannot land on a line | `place_label` measures a label against the frame and against other labels, which covers clipping and collision but not the line itself. Each chart works around it by passing the `first` placement that suits its own geometry — `ABOVE` on a shallow curve, `BESIDE_BELOW` on a steep one. That is a judgement about one report's data baked into the renderer, and it is wrong the moment a curve changes shape | `tools/charts/labels.py` — `ABOVE` / `BESIDE` / `BESIDE_BELOW`, and the three `first=` call sites in `frontier.py` and `cost.py`. Sampling the polyline into small boxes and passing them as `soft` would derive it instead; the two-pass machinery already exists |
| 8 | Decide whether a serving path needs its own split chart, or whether `split-jobs.csv` should take its axis column from the header like its workload columns | the split schema requires `n_set` and labels the axis `N set`, which is the jobs profile's axis. The same per-workload decomposition over a serving path is indexed by offered rate, and there is no way to say so — so a report on the api profile can chart its floor and its amortization but not where its serving cost goes | `tools/charts/cost.py` — `SPLIT_AXIS = "n_set"` and `axis_label(ax, "N set")` in `jobs_split`. Five chart types, and this is the only one bound to one profile's axis |
